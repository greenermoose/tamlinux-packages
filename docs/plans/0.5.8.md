# Tamlinux 0.5.8: Micro migration and settings recovery

Status: Develop preparation; activation awaits the user's exact Test instruction.
Scope: preserve the recorded 0.5.7 candidate and prepare its clipboard follow-up.

## Changes and validation

The product accepts existing Micro JSON5 bindings, preserving comments and
unrelated bindings while adding mouse copy/paste. Scoped buffer maps agree
with top-level mouse keys. Duplicate keys and malformed input are conflicts;
no live configuration is rewritten to get past a conflict. Shipped defaults
remain ordinary JSON. The command package supplies the JSON5 reader.

The finite settings checkpoint includes `micro/bindings.json`, retaining its
original bytes, mode or absence and archiving later writes during restoration.
The 2026-10-21 nixpkgs and Home Manager revisions selected for 0.5.7 remain
pinned. They have package/build evidence, not physical acceptance on this host.

Focused source tests cover comments, trailing commas, scoped buffer maps,
ambiguity, repeat conversion, rollback and recovery of existing/absent files.
The installed helper contract exercises the packaged JSON5 dependency and
Micro checkpoint/restore behavior.

## Apply clipboard migrations after authorized Test

Close Micro and existing Foot sessions before changing their settings. Resolve
the candidate's command package from its delivery record. Use that exact
packaged helper, never the source checkout or a PATH development override.

1. Plan `foot-theme` in a fresh journal under
   `$XDG_STATE_HOME/tamlinux/migration/` (default `~/.local/state`). Pass
   `--only foot-theme` to `plan`. Inspect original and proposed bytes, selected
   roots and conflicts. It composes the theme include repair and mouse keys.
2. Plan `micro-bindings` in a separate fresh journal with
   `--only micro-bindings`. Inspect that personal shortcuts and comments survive.
3. Review the concrete journals and rollback commands before requesting
   approval to apply. Apply each journal without `--only`; do not apply a full
   legacy migration. Any changed-since-plan file needs a fresh plan.
4. Keep both journals and the exact packaged helper reachable for rollback.
   Roll back these journals with this helper before switching to an older
   package, whose recovery manifest may differ. Recovery archives later writes.
5. Start fresh Foot and Micro sessions. Verify their effective configuration
   and clipboard backend before recording physical results.

If a file was absent and initialized by the candidate, use the candidate's
settings checkpoint to restore original absence. A journal planned after
initialization cannot establish pre-initialization absence.
