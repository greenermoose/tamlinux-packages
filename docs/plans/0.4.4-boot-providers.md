# Independent boot providers for 0.4.4e

Review the source before building, and select exact archive hashes only after
artifact inspection and isolated replacement/generation/recovery rehearsal.
The selected inputs and artifacts are in
[`boot-selection.json`](../../contracts/providers/boot-selection.json), with
unchanged AUR recipes and origins alongside the existing provider recipes.

Selected upstream-author builds are `limine-mkinitcpio-hook 1.40.0-1` and
`limine-snapper-sync 1.32.1-1`. Their origins record AUR commits, source commits,
recipe/build-script hashes and artifact digests. These are reviewed unsigned
local builds, not packages signed by Arch. `stage-providers.py` verifies archive
digests, metadata and the `.BUILDINFO` recipe hash before staging them.

The isolated native Arch build uses the unchanged recipes, including their
checksum-verified GraalVM inputs. Gradle resolves its upstream build/plugin
dependencies; the development evidence retains resolved dependency hashes.
This is a recorded build, not a claim of a fully offline or bit-reproducible
Gradle dependency lock.

[`Development evidence`](../evidence/0.4.4e-boot-provider-review.json) records
masked installation without EFI/firmware changes, UKI generation with the
staged initramfs configuration, both EFI destinations, nine-to-six snapshot
retention and old-provider/file restoration while preserving later settings.
The guest used Btrfs and a plain FAT EFI mount. Physical-host kernel/loader
versions and encrypted-root behavior require their own Test observations.

`tools/boot-checkpoint.py` captures an explicitly reviewed file set and exact
old package archives, preserving numeric owners, modes, symlinks, ACLs and
xattrs. It refuses existing destinations and live pacman locks, checks for
changes during capture, and verifies every archived file and retained package.
It records package reasons, firmware state and relevant writer states without
changing them. Its output is a recovery artifact, not permission to apply it.

Consumer source supplies the configuration, forward/inverse path set and
checkpoint specification. A final transaction uses separate temporary hook
masks outside package-owned paths, then verifies the normal update hooks are
enabled. The native login package can remain the exact d artifact because
this candidate changes boot providers and consumer boot policy.

Prepare and commit the e package assembly only after these provider pins and
the recovery/write set are known. Test, each privileged mutation, reboot,
Run and later old-package removal remain explicitly authorized operations.
