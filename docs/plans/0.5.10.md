# Tamlinux 0.5.10 preparation

Status: candidate prepared for Test. The running desktop remains on 0.5.9;
0.5.10 activation requires the maintainer's explicit Test instruction.

## Scope

- Remove the traditional visual screensaver while retaining idle power saving,
  optional locking, wake and Stay Awake.
- Develop Tamarack dark and light appearance from shared colour tokens, with
  Atkinson typography and preserving theme switching and recovery.
- Explain the operating-system and workstation layers. Provide text-login
  orientation to `hi` and `tam-desktop`, retaining visible boot progress.
- Include any ready input fixes and retain the previously accepted workflows.
- Add the approved Start menu: visible Quick Launch and Settings groups,
  right-click on unused bar space, and SUPER + right-click anywhere. Palette
  and text-size changes cover the shell, supported apps and terminals.
  [Product plan](../../../tamlinux/docs/plans/start-menu.md).

## Evidence and remaining work

tests and an installed-component development build. The build checks fresh
Tamarack selection, both Atkinson font families and the active theme-directory

`/nix/store/532zf0whzjs3hl963m0rhf8fxbskpwd8-tamlinux-installed-components`).

Finish the application and shell surface, contrast and opacity audit; establish
the achievable command-level boot visibility; and physically try theme recovery.
The keybinding plan also requires reconciliation with the host's personal map,
application conflict checks and Fred's physical acceptance. The previous
personal map has both Quick Launch and window resize on SUPER + right-click;
the reviewed cutover below resolves that overlap.

Start menu source now includes the packaged chord and moves mouse resizing
to SUPER + ALT + right-click. The consumer has a version-gated activation
step that preserves and removes its exact legacy Quick Launch override;
custom overrides stop activation for review. Keep that preserved source in
the settings recovery scope: reverting a generation alone does not restore
a file behind a live link. The consumer change has not been activated.
Focused checks cover a compact 15-entry menu, enlarged text, pointer and
keyboard input, a scaled output with a negative origin, JSONC reloads and
appearance-setting failure recovery. Physical acceptance remains pending.

## Test the menu after authorized activation

Use the digest-bound Test plan. Verify retained mutable-settings recovery
covers shell/theme choices and the personal binding source before activation;
keep later user writes through recovery. Reuse the existing recovery anchor
and capture only any newly affected state.

- Right-click unused space on each bar: Start should open below it.
- SUPER + right-click over an app on each output: Start should open near the
  pointer, with both Quick Launch and Settings exposed.
- Check widget-specific right-clicks, keyboard navigation, search and dismissal.
- Choose a palette and text size, check shell/supported apps/terminals, return
  to the preferred values and verify persistence. Existing Foot windows need
  a restart for a new text size.
- Complete the separate native step, idle-energy reading and physical workflow
  confirmation before declaring Test complete or requesting Run.

The complete 0.5 checklist still requires physical trials on both machines,
startup timing, idle energy, recovery and the developer's appearance and
workflow acceptance. A final 0.5 release requires the exact candidate to
complete Test, Run and Release in order; a build does not establish that result.
