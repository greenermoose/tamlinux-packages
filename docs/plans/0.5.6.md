## 2. Correct imv preservation before packaging

The migration and fresh default are appropriate to the input scope, but two
review findings must be resolved:

1. `desktop/migration/engine.py` recognizes only an equals-delimited Escape
   binding and misses a binds section preceded by a UTF-8 BOM. The installed
   INI parser accepts colon-delimited bindings and BOM-prefixed files; the
   converter adds a second Escape action to those configurations. It also
   misses section headers with trailing text accepted by that parser.
   Recognize supported syntax without rewriting unrelated bytes, or refuse
   ambiguous input with an actionable conflict. Never add a competing quit
   action to an existing custom Escape binding.
2. `desktop/session/initialize.py` creates the XDG imv default when that one
   path is absent, even if a legacy personal config exists. Since imv searches
   the new path first, this hides existing customizations. Respect imv's
   documented configuration precedence, including custom XDG roots and
   explicit config selection. Preserve legacy files and links; do not silently
   introduce a higher-priority default over a personal configuration.

Add focused regressions for these cases, alongside ordinary LF/CRLF bytes,
missing section, duplicate sections, existing Escape, permissions, symlinks,
changed-since-plan rejection, repeat apply and rollback. Verify parser behavior
against the installed imv/parser, not solely a second approximate parser.
Document the policy for system fallback configuration as part of the fix.

Run the application-default and migration tests in temporary roots. Confirm
the targeted journal contains only imv, ignores unrelated redirected paths,
and restores original bytes and modes. No live migration is part of this step.

Exit evidence: reviewed fixes and passing regressions; the real user config
remains untouched until its packaged migration is separately reviewed.
